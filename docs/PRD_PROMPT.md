# PRD — 노션 연동 견적서 웹 뷰어 (MVP)

> Claude Code 에 그대로 전달하는 PRD 겸 구현 프롬프트.
> 프로젝트 공통 규칙은 `CLAUDE.md` / `AGENTS.md` 를 따른다. 이 문서와 충돌하는 부분은 §9 에 명시했다.

## 1. 한 줄 요약

노션 데이터베이스에 입력한 견적서를, **클라이언트가 공유 링크로 웹에서 열람**하고 **PDF 로 내려받을 수 있게** 하는 읽기 전용 웹앱.

## 2. 배경 · 목표

- 견적서 작성/관리는 **노션**에서 한다 (작성자는 익숙한 도구 그대로 사용).
- 클라이언트에게는 노션 접근 권한을 주지 않고, **깔끔한 견적서 페이지 링크**만 전달한다.
- 클라이언트는 링크로 열람하고 PDF 를 저장/인쇄한다.

**MVP 성공 기준**: 노션에 견적서 1건을 입력 → 링크 공유 → 클라이언트가 모바일/PC 에서 열람 → PDF 다운로드까지 막힘 없이 된다.

## 3. 사용자

| 역할 | 하는 일 | 로그인 |
|---|---|---|
| 작성자(나) | 노션에서 견적서 입력, 링크 복사해 전달 | 노션만 사용, 웹앱 로그인 없음 |
| 클라이언트 | 링크로 견적서 열람, PDF 다운로드 | 없음 (링크 소유 = 접근 권한) |

## 4. 범위

### In (MVP)
1. 노션 DB 에서 견적서 1건 조회 → 웹 페이지 렌더링
2. 견적서 목록 페이지 (작성자용, 링크 복사)
3. PDF 다운로드 버튼
4. 반응형 + 다크모드 + 인쇄 최적화(A4)
5. 존재하지 않음/비공개/노션 오류 상태 처리

### Out (하지 말 것)
- 웹앱에서 견적서 생성·수정 (입력은 노션에서만)
- 로그인/회원가입, 결제, 전자서명, 승인/거절 버튼
- 이메일 발송, 다국어, 견적서 버전 이력
- DB 도입, 자체 백엔드

## 5. 노션 데이터 구조

### 5-1. 견적서 DB (properties)

| 속성명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 견적번호 | Title | O | 예: `Q-2026-001` |
| 클라이언트명 | Text | O | |
| 담당자 | Text | | 클라이언트 측 담당자 |
| 발행일 | Date | O | |
| 유효기간 | Date | | 견적 유효 만료일 |
| 상태 | Select | O | `작성중` / `발송` / `확정` / `만료` |
| 공개 | Checkbox | O | 체크된 건만 웹에 노출 |
| 공유토큰 | Text | O | 추측 불가 랜덤 문자열(예: nanoid 21자). URL 에 사용 |
| 비고 | Text | | 하단 안내 문구 |
| 세율 | Number | | 기본 10 (%) |

### 5-2. 품목 (페이지 본문 안 inline 테이블 DB 또는 별도 하위 DB)

| 속성명 | 타입 |
|---|---|
| 품목명 | Title |
| 설명 | Text |
| 수량 | Number |
| 단가 | Number |

- **금액(소계/세액/합계)은 노션 값이 아니라 웹에서 계산한다** (수량×단가 → 소계 → 세액 → 합계). 노션 수식 의존 금지.
- 품목 연결 방식(inline 테이블 vs 별도 DB + Relation)은 구현 시 노션 API 문서를 확인해 **더 단순한 쪽**을 택하고, 선택 이유를 한 줄로 보고한다.

## 6. 화면 · 라우트

| 경로 | 설명 |
|---|---|
| `/` | 서비스 소개 + 안내 (간단히) |
| `/invoices` | 작성자용 목록 (견적번호·클라이언트·발행일·상태·링크 복사). 공개 체크된 건만 |
| `/invoice/[token]` | **핵심 화면.** 견적서 상세 + PDF 다운로드 버튼 |

### `/invoice/[token]` 레이아웃 (A4 문서 형태)
1. 헤더: 견적서 제목, 견적번호, 발행일, 유효기간, 상태 배지
2. 수신(클라이언트명·담당자) / 발신(공급자 정보 — 환경변수 또는 상수로 설정)
3. 품목 테이블: 번호·품목명·설명·수량·단가·금액
4. 합계 박스: 공급가액 / 세액 / **합계**(강조)
5. 비고
6. 상단 고정 액션바: `PDF 다운로드` (인쇄 시 숨김)

### 상태 처리
- 토큰 불일치 / 공개 해제 → 404 (존재 여부를 노출하지 않는다)
- 노션 API 실패 → 안내 메시지 + 재시도 안내, 스택 노출 금지
- 만료(유효기간 경과) → 상단에 "유효기간이 지난 견적서입니다" 배너, 열람은 허용
- 로딩은 `loading.tsx` / Suspense 스켈레톤

## 7. 기능 요구사항

| ID | 요구사항 | 우선 |
|---|---|---|
| F1 | 서버 컴포넌트에서 노션 API 로 견적서·품목 조회 (토큰은 서버 전용 환경변수) | P0 |
| F2 | 공유토큰으로 단건 조회, `공개` 체크된 건만 반환 | P0 |
| F3 | 금액 계산 유틸 (순수 함수, 천 단위 콤마, 원 단위 반올림) | P0 |
| F4 | 견적서 상세 렌더링 (§6 레이아웃) | P0 |
| F5 | PDF 다운로드 (파일명 `견적서_{견적번호}_{클라이언트명}.pdf`) | P0 |
| F6 | 목록 페이지 + 링크 복사(sonner 토스트) | P1 |
| F7 | 반응형(모바일 우선) + 다크모드 + 인쇄 CSS | P1 |
| F8 | 노션 응답 캐싱·재검증 (노션 수정이 합리적 시간 내 반영) | P1 |

### PDF 방식 (결정 필요 → 기본값 지정)
- **기본값**: `@react-pdf/renderer` 로 PDF 전용 컴포넌트를 클라이언트에서 생성 (Route Handler 불필요 → 규칙 준수). **한글 폰트(Noto Sans KR)를 임베드**해야 글자가 깨지지 않는다.
- 대안: 브라우저 인쇄(`window.print()` + `@media print`) — 구현은 가장 쉽지만 "다운로드" 경험이 약하다.
- 구현 전 두 방식의 한글 렌더링을 짧게 검증하고, 선택 결과를 보고한다.

## 8. 비기능 요구사항

- **보안**: 노션 토큰·DB ID 는 `.env.local` 에서만 읽고 클라이언트 번들·로그·응답에 노출 금지. `.env.example` 에 키 이름만 커밋.
- **접근 제어**: 링크 소유 = 접근 권한. 토큰은 추측 불가여야 하며, 목록 `/invoices` 도 `공개` 체크 건만 노출.
- **검색 노출 방지**: `robots` noindex (견적서는 비공개 문서).
- **성능**: 상세 페이지 LCP 2.5s 이내 목표 (캐시 적중 기준).
- **접근성**: 표 `th scope`, 색상 대비, 키보드 포커스.
- **개인정보**: 클라이언트 연락처·금액을 로그(`console.log`, 에러 메시지)에 남기지 않는다.

## 9. 기술 제약 — `CLAUDE.md` 와의 관계

스택은 `CLAUDE.md` 그대로: Next.js(App Router) · TypeScript · Tailwind v4 · shadcn/ui(Base UI) · next-themes · sonner.

| 기존 규칙 | 이 프로젝트에서의 적용 |
|---|---|
| "서버/DB/API 라우트를 만들지 않는다" | **유지.** Route Handler/DB 없음. 단, 노션 조회는 비밀 키가 필요해 브라우저에서 불가 → **서버 컴포넌트에서 직접 호출**하는 것만 예외로 허용 (`src/lib/notion/` 에 격리). |
| "데이터는 persist 스토어에" | 견적서 원본은 노션이 소스. Zustand 는 UI 상태(필요 시)에만. 견적 데이터를 localStorage 에 저장하지 않는다. |
| 폼은 RHF + zod | 입력 폼 없음. 단, **노션 응답은 zod 로 파싱·검증**한다 (`lib/schemas/invoice.ts`). |
| `asChild` 없음 (Base UI) | 링크 버튼은 `<Link className={buttonVariants()}>` 또는 `render={...}`. |
| 동적 라우트 + `cacheComponents` | `/invoice/[token]` 은 토큰을 사전에 알 수 없다. **구현 전 `node_modules/next/dist/docs/` 에서 동적 라우트·캐싱·`generateStaticParams` 규칙을 읽고** 빌드가 통과하는 방식으로 구성한다. |

> ⚠️ 이 Next.js 는 학습 데이터와 다르다. API 를 쓰기 전 반드시 `node_modules/next/dist/docs/` 를 확인한다.

### 폴더 구조 (제안)

```
src/lib/notion/client.ts        노션 클라이언트 (server-only)
src/lib/notion/invoices.ts      견적서/품목 조회·매핑
src/lib/schemas/invoice.ts      zod 스키마 + 파생 타입
src/lib/invoice-calc.ts         금액 계산 순수 함수
src/components/invoice/         InvoiceView, ItemsTable, TotalsBox, StatusBadge, PdfButton, InvoicePdf
src/app/invoices/page.tsx
src/app/invoice/[token]/page.tsx  (+ loading.tsx, not-found.tsx)
.env.example                    NOTION_TOKEN, NOTION_INVOICE_DB_ID, 공급자 정보 키
```

## 10. 수용 기준 (Definition of Done)

- [ ] 노션에 입력한 견적서가 `/invoice/[token]` 에 표시되고, 합계가 수동 계산과 일치한다
- [ ] `공개` 해제 또는 잘못된 토큰이면 404
- [ ] PDF 가 다운로드되고 **한글이 깨지지 않으며** A4 한 장에 레이아웃이 유지된다 (품목이 많으면 페이지 넘김)
- [ ] 모바일(375px)·데스크톱 모두 가로 스크롤 없이 열람 가능, 다크모드 정상
- [ ] 노션 토큰이 클라이언트 번들에 없음 (빌드 산출물 검색으로 확인)
- [ ] 금액 계산 유틸 단위 검증 (0원, 소수 수량, 세율 0/10, 반올림 케이스)
- [ ] `npm run lint` → `typecheck` → `build` 통과, 커밋 전 `/validation`

## 11. 구현 순서 (Claude Code 작업 지시)

각 단계가 끝나면 멈추고 결과를 요약 보고한 뒤 다음으로 진행한다.

1. **준비**: `node_modules/next/dist/docs/` 에서 동적 라우트·캐싱 문서 확인 → 계획 요약. 노션 SDK(`@notionhq/client`) 설치, `.env.example` 작성.
2. **데이터 계층**: zod 스키마 → 노션 조회/매핑 → 금액 계산 유틸. (UI 전에 mock 데이터로 계산 검증)
3. **상세 페이지**: 레이아웃·상태 처리(404/에러/만료)·로딩·인쇄 CSS.
4. **PDF**: §7 방식 비교 검증 후 구현, 한글 폰트 확인.
5. **목록 페이지 + 링크 복사**, 헤더 NAV 추가(`site-header.tsx`).
6. **마무리**: noindex, 반응형/다크모드 점검, 수용 기준 체크리스트 점검, `/validation`.

## 12. 열린 질문 (작성자 확인 필요)

1. 공급자(내 회사) 정보: 상호·사업자번호·주소·연락처·직인 이미지 — 어디서 관리? (기본: 환경변수/상수)
2. 통화는 원화(KRW) 고정이면 되는가? 다중 통화 필요?
3. 노션 반영 지연 허용 범위 (기본: 수 분 캐시)
4. 링크에 추가 보호(비밀번호/만료일) 필요 여부 — MVP 는 **없음**으로 가정
